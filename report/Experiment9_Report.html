1. Aim

To design test cases for a web application and execute them using Selenium IDE (functional testing), and to perform a basic load/performance test using Apache JMeter, recording response time and throughput (non-functional testing).

2. Application Under Test

Orbital Sentinel is an early-warning health-monitoring system for satellite fleets (see the SRS and the earlier ER and state-transition experiments). For this experiment, a minimal working build of the system was developed to cover the operator's alert workflow:

  • Login page — email/password login for the Analyst (Operator) user.
  • Alert dashboard — a risk-ordered alert list (SRS REQ-16) showing Alert ID, Satellite, Risk Level, Severity, Created At and Status.
  • Acknowledge alert — moves an alert from AlertRaised to Acknowledged, as in the state transition diagram (Experiment 5).
  • REST API — POST /api/login, GET /api/alerts, POST /api/alerts/:id/acknowledge.

The data model uses the entities from the ER diagram (Experiment 4): Satellite, Detection, Alert and User. The data is mock data held in memory: 5 satellites, 8 detections and 8 alerts.

4.4 Analysis

  • Response time: the average response time was 6–7 ms on all endpoints, and 90% of requests completed within 12 ms. The slowest request of the whole test took 38 ms (login).
  • Throughput: the system handled about 150.7 requests/sec in total (about 50 requests/sec per endpoint) with 50 concurrent users.
  • Reliability: 0.00% errors across 1,500 requests. Every response returned HTTP 200 and passed its assertions.
  • Stability: the low standard deviation (about 4 ms) shows consistent response times under load, with no sign of degradation as users ramped up.
  • The SRS performance requirement (dashboard updates within about one second) is met with a large margin for these operations. Because the build uses in-memory mock data, these figures are a baseline; they should be measured again once the real database and detection pipeline are integrated.

6. Conclusion

Test cases were designed for the Orbital Sentinel web application and executed with Selenium IDE. Login validation and the alert-acknowledgement workflow (AlertRaised → Acknowledged) behaved as specified in all executed tests. A load test with Apache JMeter on the application's REST API recorded an average response time of 6 ms, a 90th-percentile time of 12 ms, a throughput of 150.7 requests/sec and a 0% error rate with 50 concurrent users. This shows the application is functionally correct for the tested features and responsive under moderate load. Both tools were used successfully to carry out functional and non-functional testing.
